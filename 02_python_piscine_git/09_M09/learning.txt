Pydantic is a data validation and settings management library for Python
Pydantic uses type hints to help you validate and serialize your data schemas, making your code more robust, readable, concise, and easier to debug

Enum allows to represent different options and use them when choosing (eg different dpt from a compaany)

Validators are used to make more complex validation systems, which allows to apply custom validatio logic to your BaseModel fields
Different types of validators can be used:
	- After Validator: run after Pydantic's internal validation. 
	They are generally more type safe and thus easier to implement
	They can be used either:
		- using the annoted pattern
			def is_even(value: int) -> int:
				if value % 2 == 1:
					raise ValueError(f"{value} is not an even number")
				return value

			class Model(BaseModel):
				number : Annoted[int, AfterValidator(is_even)]

		- using the @field_validator decorator, applied on a class method
			class Model(BaseModel):
				number : int

				@field_validator("number")
				@classmethod
				def is_even(cls, value: int) -> int:
					if value % 2 == 1:
						raise ValueError(f"{value} is not an even number")
					return value
	- BeforeValidator: run before Pydantic's internal parsing and validation.
	These are more flexible than aftere validators, but they also have to deal
	with the raw input, which in theory could be any arbitrary object. You should
	also avoid mutating the value directly if you are raising a validation error 
	later in your validator function, as the mutated value may be passed to other validators
	if using unions.
	The value returned from this callable is then validated against the provided type annotation by Pydantic
	They can be used either:
		- annoted pattern
		def ensure_list(value: Any) -> Any:
			if not isinstance(value, list):
				return [value]
			else:
				return value
		
		class model(BaseModel):
			numbers: Annotated[list[int], BeforeValidator(ensure_list)]
		- decorator:
		class Model(BaseModel):
			numbers: list[int]

			@field_validator("numbers", mode="before")
			@classmethod
			def ensure_list(cls, value: Any) -> Any:
				if not isinstance(value, list):
					return [value]
				else:
					return value
	- Plain validator: act similarly to before validators but they
	terminate validation immediately after returning, so no further
	validators are called and Pydantic does not do any of its internal
	validation against the field type
	They can be used either:
		- Annoted pattern:
		def val_number(value: Any) -> Any:
			if isinstance(value, int):
				return value * 2
			else:
				return value
		
		class Model(BaseModel):
			number: Annotated[int, PlainValidator(val_number)]
		- Decorator:
		class Model(BaseModel):
			number: int

			@field_validator("number", mode="plain")
			@classmethod
			def val_number(cls, value: Any) -> Any:
				if isinstance(value, int):
					return value * 2
				else:
					return value
		- wrap validators: are the most flexible as they can run before or after
		Pydantic and other validators process the input, or they can terminate 
		validation immediately, either by returning the value early or by raising 
		an error. 
		They must be defined with a mandatory extra handler parameter: a callable
		taking the value to be validated as an argument. Internally, this handler will 
		delegate validation of the value to Pydantic. You are free to wrap the call to 
		the handler in a try..except block, or not call it at all.
			- Annoted pattern:
			def trucate(value: Any, handler: ValidatorFunctionWrapHendler) -> str
				try:
					return handler(value)
				except ValidationError as err:
					if err.errors()[0]["type"] == "string_too_long":
						return handler(value[:5])\
					else:
						raise

			class Model(BaseModel):
				my_string: Annotated[str, Field(max_length=5), WrapValidator(truncate)]
	
			- Decorator
			class Model(BaseModel):
				my_string: Annotated[str, Field(max_length=5)]

				@field_validator("my_string", mode="wrap")
				@classmethod
				def truncate(cls, value: Any, handler: ValidatorFunctionWrapHandle)
					try:
						return handler(value)
					except ValidationError as errL
						if err.errors()[0]["type"] == "string_too_long":
							return handler(value[:5])
						else:
							raise


	
	Difference between annotated pattern and Decorator
		- Using annoted patterns allow to make validators reusable
		It is also easier to understand which validators are applied
		to a type, by just looking at the field annotation
			def is_even(value: int) -> int:
				if value % 2 == 1:
					raise ValueError(f"{value} is not an even number")
				return value
			
			EvenNumber = Annotated[int, AfterValidator(is_even)]

			class Model1(BaseModel):
				my_number : EvenNumber
			
			class Model2(BaseModel);
			other number : Annotated[EvenNumber, AfterValidator(lambda v: v +2)]
		- Using the decorator allws to apply the function to multiple fields.
			class Model(BaseModel):
				f1: str
				f2: str

				@field_validator("f1", "f2")
				@classmethod
				def capitalize(cls, value: str) -> str:
					return value.capitalize()
